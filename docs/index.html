code-search + code-graph

Find the code. Follow the relationship. Show the evidence.

Two local MCP backends turn a source checkout into searchable, attributable code intelligence. Search discovers relevant code by meaning and exact signals. Graph explains structure and relationships. Typed references keep every consequential answer tied to source, generation, resolver, and assurance.

The product thesis General code search is crowded. The differentiator here is a narrower, defensible promise: help an agent discover a claim, select immutable evidence for it, follow only the relationships it needs, expose the evidence tier, and escalate when the requested assurance exceeds the backend.
One operating model

Discovery and proof are different jobs.

Search is optimized for relevance. Graph is optimized for structure. Neither should manufacture certainty. The host composes them and selects backend-issued evidence.

code-search

High-recall discovery with a fail-closed index.

`code-search` combines vector similarity and FTS5 lexical retrieval, then gives the host exact source-line evidence candidates instead of asking a model to invent coordinates.

Chunk
17 language modes, 21 extensions, semantic boundaries, bounded adjacent merging.
Index
Contextual embeddings in FAISS plus code and metadata in SQLite FTS5.
Retrieve
Weighted RRF, explicit code-signal boosts, optional PPR, optional reranking.
Attest
Broad retrieval context plus exact nonblank source-line evidence candidates.

Index lifecycle

  • Capture source identity before and after construction.
  • Use a Merkle DAG for additions, changes, and deletions.
  • Validate candidate artifacts before immutable generation publication.
  • Keep current and prior manifests so readers can reject corruption and use a verified last-good generation.
  • Scope storage by project and embedding provider under ~/.claude_code_search.

Use it for

  • Natural-language “where is…” questions.
  • Exact literals, paths, qualified symbols, error strings, and acronyms.
  • Similar implementation discovery and file localization.
  • Project-balanced discovery across local indexes.
  • Atomic source evidence for a claim already identified.
Do not confuse a retrieval chunk with minimal evidence. A chunk is intentionally broad enough to provide context. The evidence adapter separately emits exact source-line candidates. Select those IDs; do not transcribe or manufacture a range.
code-graph

Persistent relationships with visible precision tiers.

`code-graph` parses 27 languages into isolated SQLite graphs, resolves and enriches relationships, and exposes 40 bounded MCP tools plus a read-only Cypher subset.

Parse
Discover files and extract declarations, imports, calls, fields, usages, endpoints, and config.
Resolve
Build structural and semantic edges with language-aware heuristics and optional SCIP replacement.
Enrich
Add tests, services, security, policy, history, communities, traces, and dependency context.
Query
Use dedicated tools, bounded traversal, Cypher, and relationship evidence over one coherent generation.
Default tier

Heuristic

Broad tree-sitter plus static-resolution coverage. Useful, fast, and fallible. Reflection, dispatch, DI, generated code, and ambiguous names remain hard.

Optional tier

SCIP

Compiler-derived CALLS replacement only for covered, non-drifted documents. Each attributable edge binds the exact compiler artifact digest.

Escalation

Runtime / CodeQL

Observed traces strengthen individual relationships. Variable-level taint requires CodeQL; graph connectivity is not relabeled as a security proof.

A graph edge is evidence, not documentation merely because it exists. Inspect resolver and confidence, verify the exact source, check coverage and truncation, and look for a counterexample before making a consequential claim.

Recommended use

A seven-step evidence workflow.

This sequence keeps tool use small, evidence attributable, and negative claims honest.

  1. Confirm project and index state.Check the selected repository, provider or precision tier, source revision, generation, freshness, and live identity.
  2. Use the cheapest exact operation first.Try a literal, symbol, path, or keyword before semantic discovery.
  3. Use semantic search for unknown names.Retrieve a small candidate set and read broad context only to understand the likely answer.
  4. Select backend-issued source evidence.Choose the exact atomic evidence ID that supports the claim; delete every item that supports no required clause.
  5. Ask one claim-specific graph question.Trace only the caller, implementation, impact, or dependency relationship the answer actually asserts.
  6. Verify and challenge.Read source, inspect precision/resolver/coverage, look for a counterexample, and treat empty/truncated results as bounded observations.
  7. Escalate assurance deliberately.Use SCIP, runtime observations, CodeQL, tests, or human review when the requested claim exceeds heuristic search and graph capabilities.
Evidence contract

Stable IDs turn an answer into an inspectable claim.

Both backends use canonical identities. The model selects references; the host verifies that selected IDs were actually observed. Stable IDs do not make a weak source stronger—they make its strength and provenance explicit.

ReferenceWhat it bindsTypical producer
symbol_refRepository, revision, path, kind, qualified name, exact rangeSearch or graph
evidence_refTyped source, relationship, or analysis evidence in one generationSearch or graph

claim_refStable repository-scoped identity for the claim under evaluationHost/evaluator
Freshness

Identity must match

A source change during indexing blocks publication. A later live/index mismatch blocks evidence emission.

Minimality

Evidence is clause-scoped

Retrieval context helps reading. Atomic evidence supports a specific assertion. Extra context is not automatically claim evidence.

Assurance

Capability is explicit

Lexical, semantic, structural, compiler, runtime, and taint capabilities are distinct; one cannot silently satisfy another.

Why use it

The value is defensible answers, not just more context.

01

Agent grounding

Give coding agents a bounded retrieval and graph surface without stuffing an entire repository into the prompt.

02

Review and impact

Connect diffs to callers, tests, services, dependencies, and exact supporting source before a reviewer accepts a blast-radius claim.

03

Security orientation

Discover security-relevant surfaces, then hand variable-flow questions to a purpose-built analyzer instead of overclaiming from graph reachability.

04

Auditability

Carry repository, revision, generation, coordinate, resolver, and artifact identity alongside each consequential answer.

05

Local control

Keep indexes local and project-isolated; choose local embeddings and disable cloud reranking when source egress is unacceptable.

06

Honest escalation

Make uncertainty and blockers visible so a host can request compiler, runtime, analyzer, or human evidence at the right boundary.

Measured, with boundaries

Evidence is encouraging—not a universal superiority claim.

Search composition

1.0 Acc@1

A bounded four-case public head-to-head was perfect. Four cases are not statistically sufficient to grade the general platform or untested proprietary products.

Graph relationships

0.950 F1

Independent SSA/RTA oracle for scoped compiler-tier Go CALLS. Heuristic Go scope-aligned F1 measured 0.976; scope and oracle matter.

Very large repository

39.2M lines

A pinned LLVM checkout was indexed on one host. The resulting storage, indexing time, memory, and warm-query profile demonstrate operation—not class-leading efficiency.

Exact dated baselines live in each repository. Measurements bind to a revision, corpus, route, language, edge shape, hardware profile, and oracle. Do not carry a result to an unmeasured dimension.

Truth boundaries

What this stack does not claim.

Search boundaries

  • Not proven superior to general code-search platforms.
  • No Sourcegraph-scale query language, history UX, ACL model, or indexing fleet.
  • No Cursor-style editor integration, Augment-style multi-source fabric, or Greptile-style complete review loop.
  • Cross-project results are project-balanced discovery, not globally calibrated relevance.
  • Cloud embedding and reranking can transmit source-derived content.

Graph boundaries

  • The default graph is heuristic, not compiler-grade.
  • SCIP is partial and document-scoped; drifted or uncovered files remain heuristic.
  • trace_data_flow is graph connectivity, not variable-level taint.
  • Graph-only conceptual localization remains weaker than semantic search.
  • SQLite-per-project is not a distributed multi-repository organizational graph.
Never turn absence into proof without coverage. A missing result can reflect a true absence, parser coverage, heuristic miss, stale identity, drift, depth or row limits, unsupported external code, or a query mismatch. State which possibilities were excluded.
